🛠️ STM32 平衡车 · 设计总结与复用手册

这份文档按「整体架构 → 各功能模块」梳理了平衡车从传感器、控制算法到执行机构的完整设计，方便你日后复习与二开复用。

💡 阅读建议：先记住一句话——“倒立摆靠加速度维持平衡，往哪倒就往哪加速”，后面所有模块都是为这件事服务的。

MCU: STM32F10x 姿态: MPU6050 电机: TB6612 + 编码电机 算法: 互补滤波 + PID 通信: 软件I²C + 串口/蓝牙

🎯 一、项目总览

平衡车本质是一个单级倒立摆 + 差速小车。核心矛盾是：车体会自然倒下，而我们要让它“靠运动”保持直立。解决思路是双闭环 PID——内环（直立环）让它不倒，外环（速度环）让它按指令走。

📥 感知
MPU6050 给出车身倾角，编码器给出轮速。
🧠 决策
互补滤波融合角度；直立环 + 速度环双 PID 算输出。
📤 执行
PWM 驱动 TB6612 → 电机；按键/蓝牙下发指令。
🔌 保障
ADC 测电池电压 + LED 电量；调试串口回传数据。

代码采用分层结构：user/ 是应用层（电池、按键、电机、串口），my_lib/ 是通用驱动与算法库（PID、快速数学、软件 I²C、按钮、任务调度），std_periph_driver/ 是 ST 官方标准外设库。这种分层让你换芯片或换电机时，只需改 user/ 和少量库参数。

2.3 控制闭环

两个环串在一起，速度环的输出“叠加”到直立环的设定值上，最终共同决定电机 PWM：

编码器速度 → 速度环PID → 叠加 → 直立环PID(角度) → 电机PWM → 车体运动 → 反馈
记住口诀：
① 直立环管“不倒”——角度偏差多大，就给多大扭力把它扶回来；
② 速度环管“走多快”——它不直接驱车，而是“偷偷”修改直立环的平衡点，让车为了找回平衡而前进/后退。

🔋 三、电源与电量指示

源码：user/app_bat.c。两节锂电串联 ≈ 8.4V，单片机 ADC 只能吃 0–3.3V，所以必须先分压再采样。

3.1 分压采集

电池正极经 3.3k + 5.1k 电阻分压，最大分压 = 8.4 × 5.1/(3.3+5.1) ≈ 3.3V，刚好不烧引脚。ADC 用 注入通道（CH8 / PB0），由 TIM2 的 TRGO 更新事件每 1ms 触发一次转换，JEOC 中断里读数。

vbat = JDR1 / 4095 × 3.3 × (8.4 / 3.3) = JDR1 / 4095 × 8.4
// ADC1_2_IRQHandler 中：TIM2 触发 → 读出注入值 → 换算电压
uint16_t jdr1 = ADC_GetInjectedConversionValue(ADC1, ADC_InjectedChannel_1);
vbat = jdr1 / 4095.0f * 3.3 * 8.4f / 3.3;  // ≈ jdr1/4095*8.4

3.2 电量指示

三颗 LED（PA4 / PA5 / PA6）按电压分档显示，低于阈值时进入快闪模式提醒充电。

电压 vbat显示含义
> 7.9 V💡💡💡 三颗亮电量充足
> 7.4 V💡💡 两颗亮较充足
> 7.0 V💡 一颗亮偏低
> 6.5 V🌑 全灭需充电
≤ 6.5 V⚡ 快闪亏电报警
✅ 裸机技巧：快闪用状态机 + 时间戳实现，绝不写 delay() 阻塞。每进一次 App_Bat_Proc()，用 GetTick() 判断距上次翻转是否 > 100ms，才切换 stage。这样主循环始终能响应其他任务。

🚗 四、电机驱动与 PWM

源码：user/app_pwm.c。单片机引脚带不动电机，必须靠 TB6612（H 桥驱动），单片机只输出 PWM 和逻辑电平。

4.1 TB6612 驱动

TB6612 内部是 4 个 MOS 管组成的 H 桥，靠两路逻辑（AIN1/AIN2）控制正反转，靠 STBY 控制休眠，靠 PWM 引脚占空比控制“等效电压大小”。

功能引脚说明
STBY 使能PA1高=工作，低=休眠
左轮 AIN1/AIN2PA9 / PA10正反转逻辑
左轮 PWM（PWMA）PA8 = TIM1_CH1占空比→电压
右轮 BIN1/BIN2PB5 / PB7正反转逻辑
右轮 PWM（PWMB）PB6 = TIM4_CH4占空比→电压
正反转真值表：AIN1=1, AIN2=0 → 正转AIN1=0, AIN2=1 → 反转
左右轮对称：车要前进时，一轮正转、另一轮必须反转（代码里交换正反转逻辑）。

4.2 PWM 参数

用定时器输出比较 PWM1 模式：计数器 CNT < CCR 时输出高。参数选取原则——

分辨率 = 1000
ARR = 999，最小占空比 0.1%，调速细腻。
频率尽量高
PSC = 0 → 72MHz/1000 = 72 kHz。频率越高，电感平滑电流越好，接近直流。
占空比计算
CCR = duty/100 × 999；等效电压 Ua = Vbat × duty。

图 4-1　同一个周期里，高电平宽度 = 占空比，决定电机平均电压

4.3 代码接口

void App_PWM_Init(void);            // 初始化 STBY + 左右电机 + 两个定时器
void App_PWM_Cmd(uint8_t on);     // 0=休眠, 非0=工作
void App_PWM_Set_L(float duty); // duty: -100~+100，负=反转
void App_PWM_Set_R(float duty); // duty: -100~+100
⚠ 易错：占空比有符号，函数内部先取绝对值再算 CCR，再依据符号设置 AIN/BIN 电平。直接把负数塞进 CCR 会出乱子。

📡 五、编码器测速

电机自带霍尔编码器（11 对磁极，即每转 22 个脉冲）。用 EXTI 外部中断双边沿捕获 A 相边沿，累加“线值”。

5.1 T 法原理

M 法（固定时间数脉冲）和 T 法（固定 1 个脉冲测时间）本质都是“用平均速度近似瞬时速度”。本项目用 T 法：记录每次边沿的 us 时间戳，脉冲间隔 ΔT 内车走过的角度已知，速度 = 角度 / ΔT。

单位换算链：
线值 → 除以 减速比 20.4 = 轮胎线值 → 除以 22 × 360° = 角度 → 对时间求导 = 角速度。
正反转：A 相超前 B 相 90° 为正转；用 direction 变量（+1/-1）记录方向。

5.2 三个经典坑（必看！）

🕳 坑1 · 速度不归零：车停下后不再触发中断，t0/t1 不更新，速度永远停在最后一刻。
解法：用 max(t0 - t1, now - t0)——宁可取更大时间间隔，保证停转时 ΔT 增大、速度趋近 0。
🕳 坑2 · 换向点异常：过零瞬间 direction 仍是 ±1，算出的速度不可能是 0，波形“直上直下”。
解法：中断里检测换向（前后 direction 相反）时把 direction 记为 ±2，速度函数遇到 ±2 直接返回 0。
🕳 坑3 · 毛刺：测速函数读 now 时被中断打断，篡改 t0/t1 导致 now - t0 溢出成大数，瞬间速度=0。
解法：读 now 前关中断，拷贝好 t0/t1 再开中断，保证 now 永远 > t0。
✅ 关键字：在中断和主循环都被修改的 encoder 变量务必加 volatile，防止编译器优化掉它。

🧭 六、MPU6050 姿态解算

MPU6050 内部集成陀螺仪 + 加速度计，通过 软件 I²C（si2c）与 MCU 通信，从机地址 0xD0。

6.1 双传感器：一个快一个稳

🌀 陀螺仪（角速度）
反应极快，但有零点漂移——积分角度会随时间越偏越多。
📐 加速度计（加速度）
无累积误差（靠重力定向），但怕震动——电机一转全是噪声。

所以谁也别单独用：只用陀螺仪会慢慢倒下，只用加速度计会疯狂抖。对策是互补滤波。

6.2 互补滤波

Angle = 0.95238 × (Angle + Gyro × dt) + (1 − 0.95238) × Acc_Angle

左边 95% 信陀螺仪（管动态、快），右边 ~5% 信加速度计（管静态、纠漂移）。偏航角 yaw 所在平面与重力垂直，加速度计算不出，所以 yaw 只用陀螺仪积分。

量程换算（量完才是有意义的物理量）：
陀螺仪：raw / 32768 × 2000 （单位 °/s，量程 ±2000°/s）
加速度计：raw / 32768 × 2 （单位 g，量程 ±2g）
加速度计解出的角度是 rad，还要 × 360/π 转成度。

6.3 工程实现要点

  • 📅 固定周期：用 PERIODIC(5) 宏，每 5ms 更新一次欧拉角，给积分/微分一个恒定时间基准（原理类似 osDelayUntil，自动补偿执行耗时，无累积误差）。
  • 🧮 快速三角函数：单片机算浮点三角慢，项目用 qmath 查表法（1024 点/象限，诱导公式覆盖全周期）。姿态解算里的 atan2 必须用 qatan2，避免 atan 只有 ±90° 导致角度丢失。
  • 🔌 通信：My_SI2C_RegReadBytes / RegWriteBytes 读写寄存器；数据寄存器高低 8 位拼接成 int16_t。

🎛️ 七、PID 控制器

源码：my_lib/pid.c / pid.h，一个位置式离散 PID 通用库，直立环和速度环都复用它。

7.1 算法结构

结构体 PID_TypeDef 保存 Kp/Ki/Kd、设定值 SP、输出上下限，以及上次输入、上次误差、积分项、上次时间。

// 位置式离散 PID（基于输入本身）
error   = SP - Input;
Output  = Kp * error;                       // 比例 P
if(非首次){
  DTerm  = Kd * (LastInput - Input) / dt;   // 微分 D（用输入差分，抗设定值突变）
  ITerm += Ki * (error + LastError) * 0.5 * dt; // 积分 I（梯形面积累加）
  Output += DTerm + ITerm;
}
Output = 限幅(Output, 下限, 上限);
稳 / 准 / 快 对应谁？
快 → P（偏差越大动力越猛） 准 → I（消除静差） 稳 → D（阻尼，防超调）

7.2 工程改进（库已内置）

① 输出限幅：电机电压不可能无限，上下限设为 ±8.4V（=电池电压）。超界就截断。
② 积分限幅：积分累加容易“跑飞”导致比例失效，积分项单独限幅在 ±8.4。
③ 首次跳过 I/D：第一次运行没有“上次数据”，靠 LastTime == INVALID_TICK 判断，只算 P。
④ PID 复位：按键启停时调 PID_Reset() 清掉 LastTime / ITerm，避免上一轮残值污染下一轮。
✅ 两种入口：PID_Compute1(Input) 让库自己用输入差分算 D；PID_Compute2(Input, dInputDt) 由你直接喂微分值（传感器本身能测角速度时更准）。

🤸 八、直立环与倒立摆

倒立摆的核心思想一句话：用加速度去对抗倾角。车往哪边倒，就往哪边加速，制造一个反向惯性力把它“撑”回来。

车身前倾 θ → 直立环输出“向前加速” → 惯性力把车身往后推 → 回到竖直

直立环就是包在速度环里面的内环：它只关心“角度对不对”，不管车到底是要停还是要走。调参时一般先调直立环让它站稳，再加速度环。

⚠ 调参顺序：先只开直立环（速度环设 0），把 P 加到能站住但有点抖，再加 D 压抖动，最后才碰速度环的 I。

⚡ 九、速度环与“速度环悖论”

速度环调节车的水平速度。但它和直立环嵌套时会出现一个反直觉的现象——

🤯 速度环悖论：想减速 → 速度环让车“向后加速” → 车因为后退而前倾 → 直立环一看前倾，立刻“向前加速”扶正 → 结果速度反而变快了！越想减速越快。

根因：速度环和直立环都在抢同一个“加速度”，互相打架。解决方法是把角速度拆成两份：

ω = ω₁（维持平衡用，交给直立环）+ ω₂（加减速用，交给速度环）
✅ 解法：速度环只拿 ω₂ 和设定值 SP 比较、输出修正量；由于维持平衡产生的 ω₁ 和位移被“忽略”，速度环专心管速度、直立环专心管平衡，两者解耦。编码器测到的线速度（换算后）本身就是车的平动速度，直接作为速度环反馈即可。

📱 十、蓝牙遥控

源码：user/app_usart2.c + my_lib/usart.c + my_lib/str_cmd。手机蓝牙发指令，经 USART3 进 MCU，MCU 再通过 USART2（921600 波特）把数据转给电脑调试助手。

📥 接收
指令以 \n 结尾；RXNE 中断里逐字节写入 intbuf，遇到结束符拷贝到 transbuf 并置标志位。
🔁 三缓冲
中断缓冲 → 中转缓冲 → 进程函数缓冲，避免中断打穿正在处理的字符串。
🔍 解析
进程函数读标志位，strncasecmp 判断是不是 move，sscanf 取参数。
if(sscanf(cmdLine, "move %d %d", &turn, &move) == 2){
   // turn/move 范围 ±100，再映射成真实速度
}
✅ 注意：发送端和接收端约定好“最大速度 100 对应真实最大速度”的映射比例；strncasecmp 的 n 表示只比前 n 个字符、case 表示不区分大小写，返回 0 即匹配。

⏱️ 十二、时基与周期调度（延时 & 宏）

这是全项目的“心跳”：delay 负责回答“现在几点了”，task.h 里的宏负责“每隔多久干一次”。看懂这一章，你才能明白——姿态解算为什么必须每 5ms 跑一次、LED 快闪为什么用时间戳而不是 delay 死等。

12.1 延时实现细节

时间基准来自 Cortex-M3 内核自带的 SysTick——一个 24 位递减计数器，时钟直接来自 HCLK（72 MHz）。它的玩法很简单：从一个数一直减到 0，减到 0 的瞬间触发一次中断，然后自动重新装填、接着再减，周而复始。

图 12-1　SysTick 溢出即“过了 1ms”，中断把 ulTicks 加 1，于是 ulTicks 就是“开机至今的毫秒数”

🎯 LOAD = 71999
Delay_Init 把重装值设为 HCLK/1000 − 1 = 72000000/1000 − 1，刚好 每 1ms 溢出一次。
⏫ ulTicks++
SysTick_Handler 检测 COUNTFLAG，溢出就 ulTicks++，毫秒时基由此而来。
🔧 懒初始化
Delay_Init 用 flag 防重复配置；Delay / GetTick / GetUs 首次调用都会自动初始化。

四个接口，各管一摊

接口作用关键说明
GetTick()当前时间（ms）直接读 ulTicks，最常用；LED 快闪、PERIODIC 都靠它
Delay(ms)毫秒级延时死等（轮询 ulTicks），会占住 CPU；禁止在中断里调用
GetUs()当前时间（μs）毫秒 + VAL 折算微秒；读期间关中断防溢出错算
DelayUs(us)微秒级延时基于 GetUs 死等；短延时可用，长延时同样占 CPU
🔍 微秒怎么来的？ SysTick 每 1ms 溢出，但内部 VAL 是连续递减的。微秒 = ulTicks×1000 + (LOAD − VAL) × us_per_mini_tick。其中 us_per_mini_tick = 1000/(LOAD+1) ≈ 0.0139 μs/计数，即 VAL 每减 1 代表约 0.0139 微秒。
// GetUs() 核心：关中断保证“读毫秒 + 读计数”原子完成，
// 若读的过程中刚好溢出（COUNTFLAG），补偿 ulTicks 再读一遍
__disable_irq();
while(1){
  tick = ulTicks;
  mini_tick = SysTick->VAL;
  if(SysTick->CTRL & SysTick_CTRL_COUNTFLAG) ulTicks++;
  else break;
}
__enable_irq();
⚠ 为什么 Delay 不能乱用： Delay() 是阻塞的——调用期间整个 while(1) 主循环卡住，姿态解算、电机控制、按键全停摆。所以裸机里“周期性干活”要用下面的 PERIODIC 宏 + 时间戳，而不是 Delay。笔记里 LED 快闪强调“不能用 delay”，根因就在这。

12.2 宏的原理

宏（#define）本质是编译前的“文本替换”——预处理器先把宏名替换成定义体，再交给编译器。它不是函数，没有调用/返回开销，参数也不做类型检查。这个特点在裸机里特别香：

⚡ 零开销
就地展开，没有函数调用压栈/跳转，适合高频执行路径。
🔓 类型无关
一套 min/max 宏通吃 int / float，不用像函数那样为每个类型写一份。
🧩 生成代码
用 ## 连接符还能“拼”出变量名，实现带记忆的周期任务宏。

四个经典技巧（全用本项目真实宏举例）

① 给每个参数加括号 ( )——防止运算符优先级踩坑。
PERIODIC_START 里写 NAME##_nxt += (T)；si2c 里 scl_w(v) 写 (v)?Bit_SET:Bit_RESET。没有这对括号，T 若是 a+1 就会被错误结合。
② do{...}while(0) 包裹多语句——让宏像“一条语句”，避免 if 后接多语句的悬挂 else 问题。
OLED 的交换宏就是范例：#define swap(x,y) do{(x)=(x)+(y);(y)=(x)-(y);(x)=(x)-(y);}while(0)。
③ ## 连接符（token paste）——把参数拼进标识符。
PERIODIC_START(NAME,T) 生成 NAME##_nxt，于是 PERIODIC_START(motor,5) 就是变量 motor_nxt。多个任务互不重名。
④ 宏里藏 static 变量——让“上次时间”自带记忆，调用点不必自己声明。
PERIODIC(T) 内部 static uint32_t nxt = 0;，第一次调用后 nxt 就一直记住“下次该执行的时间”。
🕳 坑⑤ · 参数多次求值：宏是文本替换，参数会被展开多次。本项目 min/max 写成 x1>x2?x2:x1，若你传 min(a++, b)，a++ 会被执行两次而出错。记住：宏参数别带副作用（++ / -- / 赋值）。

本项目的三类宏

类别宏作用
🔁 周期任务PERIODIC / PERIODIC_START / PERIODIC_END基于 GetTick 实现“每 T 毫秒干一次”，不阻塞
🔌 位操作封装scl_w / sda_w / scl_r / sda_r把 GPIO 读写缩成一行，软件 I²C 时序更清爽
🧰 通用小工具min / max / swap类型无关的取最值 / 交换，OLED 绘图常用

PERIODIC：裸机里的“定时调度器”

笔记里写的 period(5)、osDelayUntil，在本项目裸机里就是这两个宏。它们都靠 GetTick() 判断是否“到点”，到点才往下执行、没到就跳过/返回，于是主循环不阻塞、还能保证周期恒定（自动补偿函数执行耗时，无累积误差）。

/* 简化版：靠 return 提前退出 —— 只能在 void 函数里用，且一个函数只能用一次 */
#define PERIODIC(T) \
static uint32_t nxt = 0; \
if(GetTick() < nxt) return; \
nxt += (T);

/* 通用版：用 if{...} 大括号配对 —— 可在循环体里、可放多个命名任务 */
#define PERIODIC_START(NAME, T) \
static uint32_t NAME##_nxt = 0; \
if(GetTick() >= NAME##_nxt) { \
NAME##_nxt += (T);
#define PERIODIC_END }
/* 用法示例：每 5ms 更新一次姿态，不会卡住主循环 */
void Posture_Proc(void){
  PERIODIC_START(posture, 5);
    // ... 这里就是“每 5ms 才跑一次”的姿态解算代码 ...
  PERIODIC_END
}
两种写法怎么选？ PERIODIC(T) 把 return 塞进宏——简单但反模式（只能用于 void 函数、且一个函数只能有一个周期任务）；PERIODIC_START/END 用配对大括号绕开限制，可在函数体里放多个不同名的周期任务，更通用。本项目轮询型任务几乎都长这样：Init() 配硬件，Proc() 里套 PERIODIC 周期干活。
✅ 溢出也安全： GetTick() 返回 uint32_t，连续运行约 49 天会回绕到 0。但 nxt += T 同步回绕，在无符号数回绕算术下 now < nxt 的比较依然成立，周期精度不受影响，不用额外处理。

🎯 十三、调参实战步骤

参数不是拍脑袋定的。平衡车调参有一条铁律——“先让内环保住命（不倒），再让外环学会走”。下面把笔记里的 PID 三指标（快/准/稳 对应 P/I/D）落成可操作的步骤，省得你每次重新踩坑。

13.1 总原则：先站稳，再会走

双闭环里，直立环是内环、保命（不倒），速度环是外环、管走（按指令前进/后退）。调参顺序永远是从内到外，且每动一个参数前，先想清楚它管“快 / 准 / 稳”里的哪一个。

图 13-1　调参顺序：机械中值 → 直立环 P → 直立环 D → 速度环 I → 遥控映射，层层递进

13.2 分步调参

① 机械中值标定
车竖直静置，读加速度计解出的角度作为“0°”基准。装歪会让车一直往一边倒，P/D 怎么调都救不回。
② 只开直立环（速度环输出强制为 0）
调 P：从 0 慢慢加。P 太小→直接软倒；加到“颤颤巍巍能站住、轻推能回正但不稳”即可。P 越大回正越快（对应“快”）。
调 D：在 P 基础上加 D 作阻尼。抖动/超调明显→加大 D 压住；D 太大→反应迟钝发软。
③ 开速度环（I）
只加 I 消静差，从很小开始，让车能保持匀速、消除“始终斜一个微小角度、电机嗡嗡回不到中位”。配合第九章“速度环悖论”——用 ω₁/ω₂ 解耦，速度环只比较 ω₁ 与设定值 SP，不抢直立环的加速度。
④ 遥控映射
turn / move（±100）按“最大速度 100 对应真实最大速度”的比例映射到差速与速度设定。
⑤ 限位与复位
确认输出限幅 ±8.4；user_key 启停时调 PID_Reset() 清掉 LastTime / ITerm / LastError 残值，防上一轮污染下一轮。
口诀对照：直立环管“不倒”——角度偏差多大就给多大扭力扶正；速度环管“走多快”——它不直接驱车，而是偷偷修改直立环的平衡点，让车为找回平衡而前进/后退（详见第八章、第九章）。

13.3 现象 → 原因 → 调谁（速查表）

笔记原话：稳靠 D、准靠 I、快靠 P；治震荡要“加大 D（增加阻尼）、减小 P”。落地成一张排查表：

现象根因调哪个
一松手就往一边倒 / 软绵绵站不住P 太小 或 机械中值错加大 P / 重标中值

⚠ 调参铁律：每次只动一个参数，改完就试。同时动 P 和 D 会互相掩盖，你永远不知道是哪个起作用。直立环站稳前，绝对不要开速度环——否则速度环悖论会让车“越想站住越乱跑”。
